## 切换中发现并修正的证据问题

第一条 correction 的 claim 时间早于新 runtime PID 启动时间。原因是旧 runtime 在 SIGSTOP → SIGTERM → SIGCONT 的退出窗口中恢复了一个已开始的 outbox 迭代：

- 新 projector 已从磁盘生效，因此飞书内容纠正成功；
- 旧进程内存中的 complete_outbox 尚未携带新字段，因此第一条新 receipt 被写成 UNCLASSIFIED；
- 第二条由新 runtime 处理，字段正确。

没有掩盖该异常。修复过程：

1. 验证 outbox、receipt 的 object identity、payload hash、VERIFIED 结果和 correction qualification 完全匹配。
2. 保存 mode 0600 的修复前完整行备份。
3. 使用 SERIALIZABLE、条件 UPDATE 只修复该一条 receipt 的 scope/qualification。
4. 保留原 status、verified_at、receipt_json 和远端回执不变。
5. 新增 CORRECTION_RECEIPT_QUALIFICATION_REPAIRED 审计事件，原因标为 OLD_RUNTIME_DRAIN_RACE。

最终两条 correction receipt 都是 VERIFIED / SAMPLE_AUXILIARY / SAMPLE_NONQUALIFYING。

以后涉及待投递 migration 时，不能让 STOPPED 的旧出箱进程优雅恢复后再退出；应在新 runtime 确认加载后才创建或放行 correction，或直接终止旧父进程并确认 recorder 子进程连续。
