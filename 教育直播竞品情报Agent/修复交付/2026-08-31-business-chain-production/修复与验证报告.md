# 第十部分：最近两场比较、三场版本、策略审核与知识发布——修复与验证

## 结论

本项已完成生产部署并通过验证。系统现在具备可信的业务闭环，但生产数据尚未满足生成正式比较/打法的条件，因此没有伪造业务产物。

- 比较只使用同一同行按真实 `ended_at` 排序的最近两场 FULL_SESSION / QUALIFIED / CURRENT / VERIFIED 分析。
- 单场变化只记为 EXPERIMENT；连续三场同结构才激活正式打法版本。
- 新结构连续三场才创建新版本；回到历史结构也必须连续三场，才恢复原历史版本。
- 策略候选始终 `PENDING_REVIEW`，不会自动批准。
- 正式知识只接受 nonce 已消费、allowed approver 已批准且版本完全匹配的 approval；重复运行不会重复发布。
- 候选、diff 或证据任一被篡改时，知识发布 fail closed，旧正式知识保持不变。

## 修复内容

### 最近两场比较

新增 `v3_comparison_worker.py`：

- 按 competitor ID 分组，只取最新两场合格分析；不使用 PARTIAL、SAMPLE、SUPERSEDED 或缺 VERIFIED evidence 的场次。
- 从报告模块、互动、商品承接、CTA 等结构特征生成不依赖具体措辞的结构 digest。
- 输出 SAME/CHANGED、结构相似度和逐字段差异。
- 把两侧所有 source segment ID、原文 digest 和时间范围写入 `comparison_evidence`。
- comparison artifact 自身写入 VERIFIED evidence bundle，并绑定两份上游 analysis artifact digest。

### 三场确认版本

新增 `v3_version_worker.py`：

- 每个合格 analysis 生成唯一 `version_observation`。
- 没有三场连续证据时只记录 EXPERIMENT，不创建正式版本。
- 当前版本相同结构记 STABLE。
- 新结构连续三场：创建新 ACTIVE 版本，旧版 SUPERSEDED。
- 历史结构重新连续三场：恢复原 version ID，增加 activation count，不覆盖原版本 artifact；每次恢复另存 activation artifact。

### 策略候选与 Diff

新增 `v3_strategy_worker.py`：

- 只消费 ACTIVE_CONFIRMED / HISTORICAL_RESTORED observation。
- 要求至少三场不同 session 的原始 source segment 证据。
- 创建候选 artifact、`strategy_evidence`、`knowledge_diff` 和 review item。
- candidate 始终 PENDING_REVIEW，metadata 明确 `auto_publish=false`。

### 审批后知识发布

新增 `v3_knowledge_worker.py`：

- 只消费 `object_type=strategy_candidate`、decision=APPROVED 的 approval。
- approval version 必须等于 candidate digest；必须有 `single_use=true` 和 `nonce_used_at`，即通过现有 nonce 审批路径。
- 再次验证 candidate/diff 文件哈希、根身份、三场证据和 diff base 仍是当前正式知识。
- 同一事务创建 APPROVED knowledge version、把旧版设为 SUPERSEDED、更新 candidate/diff，并写 immutable `knowledge_publish_receipt`。
- 任何失败都不切换旧正式知识。

### 调度与工作台

- Evidence worker 每轮按 comparison → version → strategy → knowledge 顺序调用四个独立 worker；每阶段异常隔离并进入 DEGRADED，不阻断证据验证。
- 飞书现有“打法版本/策略候选”表继续使用已有字段；新版本展示同行 ID、三场支持数、结构证据路径，候选展示 diff 与人工审核状态。
- 配置明确：minimum consecutive sessions=3、candidate requires review、knowledge requires approved nonce、auto publish=false。

## 验证

### 固定状态机场景

- 最近三场 A/B/C：比较只选择 B 与 C。
- 两场相同结构：SAME，similarity=1.0。
- A/A/A：第三场才激活版本 A。
- A 稳定后单场 B，再回 A：B 仅 EXPERIMENT，不创建版本。
- A/A/A → B/B/B：版本 B 激活，A 变历史。
- 再 A/A/A：恢复原版本 A，activation count 增加，不新建重复版本。
- 三场确认后：只创建 PENDING_REVIEW candidate 和 PENDING_REVIEW diff。
- 无 approval：knowledge published=0。
- 合法 nonce approval：发布一次；重复运行 published=0。
- candidate 被篡改：publish receipt=0，APPROVED knowledge=0。

## 已知边界

- 当前结构 digest 比较的是直播打法结构和证据密度，不声称理解全部语义；策略候选仍需人工判断。
- 生产尚无同一同行两场合格数据，因此真实 comparison/version 只能等待自然数据，不能用 PARTIAL 或合成数据冒充。
- 正式知识目前是本地不可变 artifact + PostgreSQL version/receipt；外部知识库的最终发布连接若未来增加，仍必须消费同一 approval 与 content hash。
