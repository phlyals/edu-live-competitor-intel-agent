# 录制、下播与整场转录最小修复

生产 Profile：`edu_live_competitor_intel`。
只修改现有三个生产文件：`runtime/bin/recorder.py`、`runtime/v3/v3_worker.py`、`runtime/v3/v3_pipeline_worker.py`。
同目录补丁以 Profile 根目录为基准，已对实际部署文件执行反向 `git apply --check` 校验。

## 修复内容

- 只读开播/下播探针不传录制时长，不再产生 `--duration None`；未知状态不伪装成下播。
- 空媒体目录允许重新启动；已有有效媒体必须续录，避免覆盖。
- STARTING 不能等同 RUNNING；使用实际文件的跨次增长证明录制已建立。120 秒无增长转失败恢复。
- 连续四次失败进入 600 秒退避，重试时间及失败次数保存在原场次元数据中，并写入事件日志；总重启次数保留审计。
- 五分钟下播确认窗口不算入录制时长。合并失败不采用未经验证的二进制拼接，不删除失败源片段。
- 存在已知重启缺口或媒体时长不匹配的历史场次不冒充 COMPLETE。
- 样本和整场转录有不同来源标识，5 分钟样本不能阻挡整场。
- 整场音频按完整媒体提取，校验媒体/音频/ASR 输入时长，保存来源摘要和 FULL_SESSION 覆盖标识；残缺音频不直接复用。
- 补齐原整场转录分支缺失的 datetime/timedelta 导入。

## 约束与验证

- 没有修改飞书入口、任务控制、商品扫描、同行发现或分析报告生成文件；`create_analysis_tasks` 函数也保持不变。
- 没有新增生产模块或外部依赖。新增文件只有测试及本次补丁交付材料。
- 最终回归集共 76 项；包含旧 COMPLETE 标签必须经过媒体覆盖复核才能用于整场转录、临时目录迁入完成目录后复用媒体编号、已有编号保持不变及冲突文件不覆盖。
- 续检修复：媒体路径变化后按原 segment_id 更新路径；避免 recording_segments 主键冲突导致两个服务反复重启。
