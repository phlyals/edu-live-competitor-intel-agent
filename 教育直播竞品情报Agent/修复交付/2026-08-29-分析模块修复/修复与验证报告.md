## 一、JSON 截断根因

旧实现同时存在三个问题：

1. 请求没有显式限制输出结构/条目数量，也没有设置 `max_tokens`。
2. 收到响应后不检查 `choices[0].finish_reason`，直接 `json.loads(content)`。
3. 单次提示要求返回数量不受限的 claims、risks、evidence_refs 等数组。

对修复前同一请求做了不保存原文的诊断：

| 指标 | 结果 |
|---|---:|
| 输入字符 | 16000 |
| prompt tokens | 10319 |
| completion tokens | **8192** |
| finish_reason | **length** |
| 输出字符 | 18092 |
| JSON | 不可解析，字符串在字符 18062 处截断 |

因此根因已经由“疑似截断”升级为**已证实达到该次请求的输出预算**。JSON mode 不能修复被 `length` 中断的半段 JSON。

DeepSeek 官方 JSON Output 指南要求明确提示 JSON，并合理设置 `max_tokens` 防止中途截断；Chat Completions 文档明确说明 `finish_reason=length` 时内容可能只返回一部分：

- https://api-docs.deepseek.com/zh-cn/guides/json_mode/
- https://api-docs.deepseek.com/api/create-chat-completion/

## 二、16000 字符根因

旧函数签名为 `transcript_text(path, limit=16000)`，最终直接执行字符串切片。它：

- 不是配置项；
- 不做 token 估算；
- 不读取模型 context；
- 会在片段行甚至正文中间截断。

本场完整格式化转录为 42,789 字符、1060 个时间戳片段；旧 16,000 字符只到 1395.72 秒，即 36.85%。当前官方模型限制远高于该输入规模，因此 16,000 不是 API 强制约束，而是应用实现缺陷。

本次取消默认截断，并在完整 segment 边界按约 5,000 字符分块。本场得到 9 块：

`0–440.78`、`440.78–856.90`、`856.90–1304.64`、`1304.64–1763.71`、`1763.71–2211.85`、`2211.85–2670.26`、`2670.26–3147.64`、`3147.64–3555.89`、`3556.15–3782.55` 秒。

## 三、修复方案

### 分块 map

- 只在完整时间戳 segment 边界分块；1060 个 segment 每个恰好归属一个块。
- 每块要求固定 JSON schema，所有字段必须是数组，每字段最多 2 项、summary 最长 80 个汉字。
- 显式 `max_tokens=4096`。最终实测每块 completion 654～1048 tokens，留有足够余量。
- 只有 `finish_reason=stop` 才允许解析。
- 空内容、`length`、非法 JSON、错类型、字段过多、summary 过长、时间戳越块全部视为失败并有界重试 3 次。
- 三次失败后 fail closed，不创建或覆盖 COMPLETE 报告。

### 确定性 reduce

- 逐块 JSON 深层校验后，由 Python 合并；不再让模型生成一个可能再次截断的总 JSON。
- 稳定去重并按 start/end 排序。
- 模型宽时间范围只用于分类；七模块时间戳由 Python 映射回真实转录 segment 的精确 start/end/source text，避免引用跨越静音 gap。
- 讲师多名称时标记 `CONFLICT`，不猜测。
- 保留旧字段 `hook/pain_points/claims/cta/interaction_patterns/risks/evidence_refs`，新增：
  - `instructor`
  - `course_content`
  - `interaction`
  - `product_handoff`
  - `product_fulfillment`
  - `modules`
  - `analysis_coverage`

### 合法 JSON 落盘

- 使用 `json.dumps(..., allow_nan=False)`。
- 内存 parse-back 后写同目录临时文件。
- 临时文件再次 parse-back 成功后才原子 replace 最终文件。
- 只有完整 artifact 成功后，生产 `once()` 才更新数据库、evidence bundle 和 outbox。

这保证的是：成功状态对应的 artifact 始终为完整合法 JSON；外部 API 持续失败时输出明确失败状态，不伪造成功 JSON。
