## 根因

旧 analysis_coverage 有三个错误：

1. timeline coverage 使用最后时间减最早时间，内部大缺口会被吞掉。
2. segment_coverage_rate 固定写成 1.0，没有记录哪些原始 segment 对应的 chunk 真正成功。
3. 没有小于 90% 时阻止正式 COMPLETE / evidence / projection 的门禁。

因此“只有 1% 内容、七模块都引用同一秒”也可能被旧策略误判为完整。

## 修复内容

1. 为不可变 transcript 中每个原始 segment 生成稳定 source ID。
2. 每个成功 chunk 持久化其 source IDs 和集合 SHA。
3. timeline coverage 使用原始时间戳区间并集除以音频总时长。
4. segment coverage 使用成功 source ID 数除以全部 eligible source ID 数。
5. 与上一部分 transcript timestamp_coverage 交叉核验：音频时长、区间并集和覆盖率必须一致。
6. FULL_SESSION、时间戳合法、所有 chunk 完成、全部 source ID 可追踪且覆盖率至少 90% 时，才允许正式完成。
7. 95% 单独作为生产目标展示；达到 90% 但未达到 95% 不会被伪装为达到目标。
8. QUALITY_BLOCKED 持久保留诊断文件，但不绑定正式 output_path、不生成正式 evidence 或投递。
9. heartbeat 持久报告 current spec 的 qualified、meets target、blocked、waiting 和 evidence pending；历史阻塞不会因下一轮空跑而消失。

## 不可变版本升级

没有覆盖旧 artifact：

- Pipeline 为同一 transcript 创建新的 spec 版本。
- 新版本仅在旧 artifact 的 source content hash、全部 chunk diagnostics、row count、start/end、finish_reason、artifact SHA 和 VERIFIED evidence 全部匹配时，才允许无模型调用重算 coverage。
- 新 artifact 写入独立 analysis ID 和独立路径。
- 新版本完成后，旧版本及其 lineage 标为 SUPERSEDED。
- 若新版本 QUALITY_BLOCKED，旧 CURRENT 不会被提前替代。

本次生产升级使用精确 revalidation，模型 API 调用数为 0；旧 artifact 的 SHA 和 mtime 保持不变。
