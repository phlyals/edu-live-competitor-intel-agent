## 根因

旧模型可以自由返回 start/end。程序只检查时间落在 chunk 首尾之间；如果模型返回 chunk 内真实空白区，merge 会把它强行贴到“最近”的逐字稿行，形成看似可审计、实际并非模型真实引用的证据。

## 修复内容

1. 每个原始 ASR segment 生成内容绑定 ID：
   - 绝对数组序号
   - 原始 start/end
   - 原始 text SHA
2. normalized_text 只用于帮助模型阅读，不参与证据内容 digest；修改清洗文本不会改原始证据 ID。
3. 模型输入格式为 source_segment_id + 原文，不向模型提供时间戳。
4. 模型输出每项只能包含 summary 和 source_segment_ids。
5. 伪造 ID、跨 chunk ID、重复 ID、旧 start/end 格式、缺字段或多余字段全部 fail closed。
6. start/end/source_text/content_digest 只能由服务端从原 transcript 回填。
7. 删除 nearest-line fallback；最终 artifact 明确记录 nearest_segment_fallback=false 和 model_generated_timestamps=false。
8. evidence worker 重新读取不可变 transcript，对全部引用逐项核对 ID、start、end、原文 digest、transcript SHA、完整 source set digest 和 artifact digest。

## 证据发布顺序

本项新增 HELD_EVIDENCE 状态：

- analysis 完成时，新版本投影与旧版本纠正投影先进入 HELD_EVIDENCE；
- Runtime 正常运行也无法提前领取；
- evidence worker 完成严格验证后，才把与该 analysis 明确绑定的消息释放为 PENDING；
- 若 evidence BLOCKED，飞书不会收到未验证结果。

这消除了上一部分部署中“旧出箱进程早于证据完成处理消息”的竞态。
