# return_code=0 严重FFmpeg错误识别：修复与验证报告

日期：2026-08-30  
范围：只增加FFmpeg stderr分类和refresh chunk成功判定；未修改finalizer、历史数据、转录、分析、验收脚本或数据库schema。

## 结论

状态：**已原子安装，专项、完整回归和生产运行边界验证PASS。**

返回码0不再自动代表分段干净成功。只要累计观察到数据完整性错误，该chunk就不能走complete_chunk路径；只有纯网络警告且时长完整时仍可继续。

## 生产证据

只读扫描356份sidecar，其中338份return_code=0：

| 分类 | 数量 |
|---|---:|
| BENIGN | 253 |
| NETWORK_WARNING | 5 |
| INTEGRITY_ERROR | 80 |

主要真实字样包括：premature end 51、demux I/O 38、invalid data 15、packet mismatch 5、packet corrupt 3、non-monotonic DTS 6、timestamp discontinuity 18、segment skipped 18。404和重连提示如果没有完整性错误，单独归网络警告。

## 修改

- 新增 `BENIGN / NETWORK_WARNING / INTEGRITY_ERROR` 分类。
- 新增稳定安全错误码，不使用原始URL或鉴权值作为机器数据。
- 覆盖真实生产字样：404/5xx、重连、超时、DNS、premature、demux I/O、invalid data、packet mismatch/corrupt、DTS/PTS、timestamp discontinuity、empty segment、codec缺失、seek失败、segment跳过和input/mux失败。
- 未识别但含error/failed/fatal的行fail-closed为 `UNKNOWN_FFMPEG_ERROR`。
- sidecar累计保存错误码；严重错误即使发生较早、被后50行日志挤出也不会丢失。
- refresh attempt保存分类和安全错误码。
- complete_chunk新增 `tail_class != INTEGRITY_ERROR` 条件。

- 共享录制器使用同目录临时文件原子replace；所有LaunchAgent PID未变化。
- 安装时已运行的recorder继续使用内存旧代码，不受替换影响。
- 15秒观察中当前活跃PID均存活，多场媒体继续增长；一场无增长属于既有流状态，不作为本次分类器成败证据。
- Retention持续 `DELETE_DISABLED`。
- 安装后扫描相关sidecar未发现原始签名值。
- 安装时已有进程不会产生新字段；首个安装后新启动并完成/快照的recorder将生成结构化分类。当前不伪造这一自然证据。

## Trade-off

- premature end和未知error采用保守判定，可能增加重试。
- HTTP 404单独只记网络警告；它仍需要后续覆盖率/相邻段连续性验证。
- 本项只收紧单段成功判定，尚未解决finalizer如何汇总所有源段和错误；这是下一项。
