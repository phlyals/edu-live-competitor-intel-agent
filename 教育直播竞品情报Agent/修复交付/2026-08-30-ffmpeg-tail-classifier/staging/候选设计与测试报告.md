# FFmpeg stderr 分类器：隔离候选设计与测试结果

## 范围

只读审查生产共享录制器；候选代码、测试和补丁全部位于本 staging 目录。未修改 production/shared/profile 文件、数据库、服务或媒体，未访问外网。

## 候选修法

1. 新增 `classify_ffmpeg_tail()`，只返回 `BENIGN`、`NETWORK_WARNING`、`INTEGRITY_ERROR`。
2. 新增 `ffmpeg_tail_error_codes()`，把 stderr 映射为稳定枚举，不把 URL 或鉴权参数作为机器可读错误信息。
3. sidecar 新增 `ffmpeg_tail_class`、`ffmpeg_error_codes`；原有 stderr tail 继续经过 URL 脱敏。
4. 每个 refresh attempt 保存同样的分类和安全错误码。
5. `complete_chunk` 除 exit code=0、时长合格外，还要求分类不是 `INTEGRITY_ERROR`。完整时长且仅出现已恢复的网络警告仍允许完成。
6. 未识别但含 ERROR/FAILED/FATAL 的行 fail-closed 为 `UNKNOWN_FFMPEG_ERROR`。

## 分类边界

- `NETWORK_WARNING`：HTTP 4xx/5xx、超时、网络 EOF、连接中断、FFmpeg 重连提示。
- `INTEGRITY_ERROR`：提前结束、HLS segment 跳过/打不开、playlist reload失败、input/demux/mux错误、媒体损坏、时间戳非单调，以及未知严重错误。
- `BENIGN`：空 stderr 或普通非错误警告。

## 测试

- 候选专项：7/7 PASS。
- 现有生产 `SharedRecorderTests` 在候选模块上重跑：12/12 PASS。
- 覆盖：三类分类、严重错误矩阵、未知错误fail-closed、code=0严重错误不完成chunk、code=0已恢复网络warning可完成、sidecar/attempt安全持久化且无原始URL。

## Trade-off

- fail-closed 会把未来未识别的 FFmpeg error 当作完整性错误，可能产生额外重试和假阳性；好处是不会把可疑段误标完整。
- 仅检查最后50行 stderr；如果严重错误发生得很早且被大量后续日志挤出，仍可能漏检。彻底解决需在 drain 时累计错误码，而不是只从尾部回算。
- `STREAM_PREMATURE_END` 一律判完整性错误，即使 FFmpeg 后来重连；这偏保守，可能重录一个实际可用的段。
- HTTP 404/5xx 单独视为网络警告；只有时长完整且没有终态完整性错误才允许，减少短暂网络波动造成的误拒绝。
- 候选没有改变最终自然下播分支的整体状态语义，只收紧 `complete_chunk`；若要让整场状态显式变成 `PARTIAL`，应由后续独立状态传播修复处理。
