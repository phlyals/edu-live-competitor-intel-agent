# 第九部分：证据验证后投递与版本去重——修复与验证

## 结论

本项已完成生产部署并通过真实飞书投递验证。

- Analysis 完成事务不再创建任何 semantic outbox；只提交不可变 artifact、analysis 状态和 `evidence_bundles.REQUIRED`。
- Evidence 在同一数据库事务中完成 schema、scope、覆盖率、source segment、artifact SHA 和血缘版本校验，然后才创建 versioned outbox。
- 每条新投影同时绑定 artifact digest、spec/model/prompt、evidence bundle、manifest hash、verified_at 和 projection version。
- 相同 projection version 重放只保留一条；同 analysis 的新 artifact digest 会得到新的 projection version。
- outbox 标记 SENT 与真实 delivery receipt 在同一事务写入；receipt 复制并锁定相同版本身份。
- 新 reconciler 可以补齐“VERIFIED evidence 但没有 outbox”，识别 “SENT 但没有 receipt”，并且绝不伪造第三方 receipt。
- 旧 `HELD_EVIDENCE` 路径不再用于新分析；生产当前数量为 0。

## 根因

旧 Analysis 会在证据尚未验证时先写 outbox，再把状态改成 `HELD_EVIDENCE`。虽然 Runtime 不会领取 HELD，但数据库里已经存在一个“待投递事实”，容易在服务版本混跑、手工状态修改或恢复流程中提前释放。

旧 outbox 去重仅依赖整个 payload hash，没有显式保存 artifact/evidence/spec 版本；delivery receipt 也只绑定 outbox ID，难以回答“远端确认的究竟是哪一版报告”。系统还缺少一个收敛器处理以下崩溃边界：

- analysis 已提交，evidence worker 尚未运行；
- evidence 已 VERIFIED，但 outbox 未创建；
- outbox 已标 SENT，但 receipt 未写入；
- receipt 已 VERIFIED，但业务 task 仍停在 DELIVERY_PENDING。

## 修复内容

### 1. 提交顺序

- 删除 Analysis worker 中所有 semantic outbox 创建和 HELD_EVIDENCE 逻辑。
- Evidence worker 显式开启事务；证据更新、重算候选切换和 versioned outbox 创建任一步失败时全部 rollback。
- 对旧报告的 STALE/SUPERSEDED 纠正也必须引用该旧报告已有的 VERIFIED evidence，不能凭状态直接投递。

### 2. 版本身份

Outbox 与 receipt 新增：

- `projection_version`
- `artifact_digest`
- `evidence_bundle_id`
- `evidence_manifest_hash`
- `evidence_verified_at`
- `projection_binding_status`

新 versioned projection 的 payload 和数据库列必须携带同一套身份。唯一索引为 destination + object type + object ID + projection version；同版本不同 payload 会 fail closed。

PostgreSQL trigger 禁止投影或 receipt 创建后修改 payload hash、projection version、artifact/evidence 身份；状态和重试字段仍可正常演进。

### 3. Reconciler

新增 `v3_projection_reconciler.py`，由 Evidence 每轮调用：

- VERIFIED CURRENT analysis 缺少目标 projection version：确定性补建；
- 旧 HELD_EVIDENCE：不直接释放，取消旧路径并创建严格版本；
- versioned outbox 的列、payload、analysis、evidence 不一致：投递前 BLOCK；
- SENT 但无 receipt：写 reconciliation + review，绝不插入伪回执；
- receipt 的 payload hash/projection version/artifact digest 不一致：REVIEW_REQUIRED；
- scan_result 已有 VERIFIED receipt 但 task 卡在 DELIVERY_PENDING：安全收敛为 COMPLETE/VERIFIED。

### 4. 历史数据

- migration 005 对 5 条已有正式 semantic outbox 回填 `LEGACY_EVIDENCE_BOUND`，保留原 payload、dedupe key 和真实 receipt，不重写历史发送事实。
- 旧 SAMPLE correction 保持非正式资格，不伪装成 evidence-verified formal projection。
- 当前正式 analysis 没有严格版本投影，因此 reconciler 创建 1 条新的 `VERSIONED_EVIDENCE` 投影；它更新同一飞书记录，不新增业务行。

- 候选 LaunchAgent Python：233 项通过，17 项跳过。

新增覆盖包括：

- analysis commit 后 evidence=REQUIRED 且 outbox=0；
- hash/schema/证据失败时 outbox 始终为 0；
- verify→enqueue 中间注入崩溃，evidence 与 outbox 一起 rollback；
- evidence 成功后只产生一条 versioned outbox，重放不重复；
- 同 analysis 新 artifact digest 产生第二个版本；
- VERIFIED bundle 缺 outbox 时 reconciler 补建；
- SENT 缺 receipt 时只建 review，不建 receipt；
- VERIFIED receipt 可收敛 DELIVERY_PENDING task；
- 8 个并发生产者写同一 projection version，只得到同一 outbox；
- 同 projection version 不同 payload 被拒绝；
- outbox/receipt 版本身份不可修改。

## 已知边界

- 外部 API 成功但客户端完全丢失响应时，无法仅靠本地数据库证明远端结果；reconciler 会要求人工核对，不会伪造 receipt。
- 5 条历史正式投影保留 `LEGACY_EVIDENCE_BOUND`，因为不能重写已经发送过的 payload；从 migration 005 起的新投影使用 `VERSIONED_EVIDENCE`。
- 通用 outbox 的 PostgreSQL 原子 claim/fencing 属于 P0-6，尚未在本项中扩大修改；本项只保证 semantic projection 的证据顺序、版本身份和收敛。
