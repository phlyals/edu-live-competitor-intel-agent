## 0. 统一实施原则

1. **先可逆安全闸，后功能修复。** 第一批只做 retention kill switch、生产门禁 fail-closed、备份和数据库权限，不触碰历史场次起止时间。
2. **历史记录保留审计，不删除、不伪造。** 旧 segment、sample transcript、sample analysis 改为明确的非业务资格状态；原行和原文件保留。
3. **旧验收脚本保持不改。** `check_recording.py`、`check_transcription.py`、`check_analysis.py` 继续作为原始子检查；新增一个生产验收策略层，组合其输出与 sidecar/manifest/coverage 证据。这样满足此前“不修改验收脚本”的约束。
4. **部署必须 drain + release manifest。** 有正在录制的场次时，不重启 recorder；先切换非录制 worker，再在安全点切 Runtime。每个常驻进程心跳必须报告加载的 release/hash。
5. **所有数据治理先 dry-run。** 先输出受影响 ID、旧值、新值和理由；人工确认后才执行同一哈希的 migration plan。

### P0-6 PostgreSQL claim/fencing 不互斥

**修法描述**

- 修改 [`v3_db.py:PostgresConnection`](/Users/mac/.hermes/profiles/edu_live_competitor_intel/runtime/v3/v3_db.py:139) 和 [`v3_runtime.py:_begin()`](/Users/mac/.hermes/profiles/edu_live_competitor_intel/runtime/v3/v3_runtime.py:216)，停止把 SQLite `BEGIN IMMEDIATE` 假装成 PostgreSQL 互斥事务；提供显式 PostgreSQL transaction API。
- 将 [`claim_task()`](/Users/mac/.hermes/profiles/edu_live_competitor_intel/runtime/v3/v3_runtime.py:337) 和 [`claim_outbox()`](/Users/mac/.hermes/profiles/edu_live_competitor_intel/runtime/v3/v3_runtime.py:531) 改为单条 CTE：`SELECT ... FOR UPDATE SKIP LOCKED` + 条件 UPDATE + RETURNING。
- schema 新增独立 `lease_epoch BIGINT`，不要复用 attempts 当 fencing token。`renew/release/complete/retry` 都必须携带 `worker_id + lease_epoch`，并在 WHERE 中校验；0 行更新即视为丢失所有权。
- 所有 `release_task()` 调用点（`v3_worker.py:760` 起）传 owner/token。outbox 长投影采用后台续租，每 30 秒更新；lease 时间大于单次不可分割步骤。
- 在部署前 drain 旧 worker，使旧签名/旧 lease 不与新代码并存。

**Trade-off**

- 接口签名会影响所有 worker 和测试；需要一次 schema migration 和受控重启。
- `SKIP LOCKED` 可使一个长期锁住的早期任务暂时被后面的任务越过，严格 FIFO 会弱化。
- 外部 API 在响应丢失时仍可能付出重复调用成本；fencing 能防重复提交状态，不能保证第三方绝对只执行一次。

**验证方法**

- 用真实 PostgreSQL 启动 20 个并发进程抢 100 个 task/outbox，每行只能被一个 epoch 领取。
- 旧 worker lease 过期后尝试 complete/retry，必须返回 ownership lost，不能覆盖新 owner。
- 投影运行超过 120 秒时 lease 持续更新，第二 worker 不得重新领取。
- 注入 claim 后崩溃、API 成功后崩溃、receipt 写入前崩溃三类故障，reconciler 能收敛。

## 三、P2 修复方案

### P2-1 数据库无 CHECK、类型全为 TEXT

**修法描述**

- 新建分阶段 migration：先加 TIMESTAMPTZ/JSONB shadow列并回填、验证；再切读写；最后增加 NOT NULL/CHECK/enum/domain。
- 对核心状态建立允许集合和状态转移约束；对 generic polymorphic 表采用对象注册表或应用级引用校验，不能硬塞错误外键。
- 更新 `v3_db.py` 和所有字符串时间比较为数据库时间比较；保持 SQLite 测试适配层只用于单元测试。

**Trade-off**

- 大迁移可能锁表；当前库不大但仍需停写窗口和回滚计划。
- enum 后续扩展需要 migration；CHECK 更灵活但类型提示较弱。
- 老数据中的混合时间/未知状态需先隔离，不能直接强制约束。

**验证方法**

- 在生产快照克隆库完成 shadow migration，逐列 count/hash 对比。
- 注入非法状态、坏 JSON、无时区时间必须被拒绝。
- 所有现有查询和104+55测试在新类型上通过，再切生产。

### P2-2 COMPLETE/VERIFIED 状态语义混用

**修法描述**

- 为媒体、转录、分析、evidence 统一拆成：`artifact_status`（文件生命周期）、`coverage_status`、`semantic_status`、`qualification_status`。
- 建立允许状态转换表/函数；下游只消费 `qualification_status=QUALIFIED`，不再从 COMPLETE/VERIFIED推断。
- 兼容期保留旧字段并由新字段单向生成展示值，禁止新代码反向读取旧字段决定业务资格。

**Trade-off**

- 字段数量和查询复杂度增加；历史报表需要重新定义。
- 兼容期存在双字段，需要一致性检查。

**验证方法**

- 58 个 PARTIAL manifest 可保持 artifact VERIFIED，但 qualification 必须 NONQUALIFYING。
- 300秒样本可以 artifact COMPLETE、coverage SAMPLE、qualification NONQUALIFYING。
- 属性测试覆盖所有允许/禁止状态转换。

### P2-3 失败 job 无终态、孤儿媒体积累

**修法描述**

- recording job 增加总尝试、总墙钟和错误类型预算；达到上限转 `FAILED_FINAL/QUARANTINED`，创建 review/outbox告警，不再无限退避。
- 新增 `v3_orphan_inventory.py` 只读盘点无 DB 引用目录，写 inventory（path/hash/bytes/mtime/推测来源）；自动删除保持关闭，人工确认后纳入 retention。
- 8 个 ENDED/WAITING_STREAM 历史 job通过 dry-run分类为无媒体、可finalize、需review三类，不直接批改。

**Trade-off**

- 总预算可能让最终可恢复的长故障提前终止；提供人工 resume 且必须新 lease/审计。
- orphan hash 盘点会产生磁盘读取负载。

**验证方法**

- 连续失败达到预算只产生一次终态和一次告警；人工 resume 后从原场次恢复但不重复对象。
- 两个约2.66GB孤儿目录出现在 inventory，未被自动删除。

### P2-4 HLS fallback 未实际执行

**修法描述**

- 修改 [`record_live_with_refresh()`](/Volumes/ExternalStorage/AgentInfrastructure/isolated/shared/avtranscribe/record_douyin_live.py:298)，对同一次 fresh resolve 返回的 `stream_urls` 按 FLV→HLS有限尝试；只在确认 LIVE 且错误属于可切换网络/协议错误时 fallback。

**Trade-off**

**验证方法**

### P2-5 cookie、argv和日志隐私面

**修法描述**

**Trade-off**
